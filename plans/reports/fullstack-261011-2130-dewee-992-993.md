## Residual risks
- Own-only matching uses the key pattern `agent:%:app:%` plus `user_id`, while session detail checks the `channel` column equals `app`. They agree for every key the chat runner builds, but a key with `app` in that position and a different channel column would differ.
- The SQL order is `updated_at DESC` with no tiebreaker, as before this change. Two chats with the same timestamp could swap places between page reads. The SQLite test spaces its timestamps 2 ms apart. A secondary sort on `session_key` would make the order stable; it is not added here.
- The PG filter was not run against a live Postgres. It uses the same `SessionListOpts` fields as the tested SQLite builder, and the PG `buildSessionFilter` already supports `UserID` and `AgentID`.
- Deploy order: the BFF with this change fails the extension sessions list with 503 until the Gateway is updated. It does not fall back to the window scan, which is intentional, so ship the Gateway first.
- #992 is stacked on `feat/957-ccp-extension-oauth`, so it lands after #957.
