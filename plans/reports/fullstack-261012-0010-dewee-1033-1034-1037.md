# Dewee #1033 / #1034 / #1037 fixes

Two PRs into `dev` in nextlevelbuilder/dewee. Issues are labelled `done` and assigned.

## PR #1045: fix/1033-1034-session-persistence (closes #1033, #1034)
https://github.com/nextlevelbuilder/dewee/pull/1045. Commits 38d65eaf and e1ef1171, based on dev 07abba35.

- **#1033 cause:** owner checks (`isProvisionedWorkspaceChatSession`: user, agent, channel `app`) failed until the first run ended. The channel was only set by the end-of-run `UpdateMetadata`.
  - **Fix:** `internal/agent/loop_context.go` writes `req.Channel` right after `SetAgentInfo` at run start.
- **#1034 cause:** the user turn is stored by the first `FlushMessages`. Finalize skipped the flush when nothing was pending, which is the state after an abort before the first delta.
  - **Fix:** `finalizeRun` sets `RunState.Canceled`, and `finalize_stage.go` flushes on a stop.
  - The `userMsgFlushed` guard keeps the user turn to exactly one copy.
- **Review blocker, fixed in e1ef1171:** a stop during a failed setup forced the flush, which could store a message the input guard or a hook had blocked, or never checked. The setup-failure path now passes `setupDone=false`.
- **Relation to #1021:** this PR touches no files that #1021 or #1022 touch, so it is not stacked. I cherry-picked it onto #1022 and checked the extension routes:
  - During the first turn, the owner gets 200 (`running:true`) on status, history and actions. Another member gets 404.
  - Abort returns 200, and history keeps "hello" once.
  - Without the fix, every owner call returns 404.
- **Tests:**
  - agent: owner and channel are set before the reply; a stop keeps the user turn once; a completed run stores it once.
  - pipeline: a stop after setup flushes; a stop during failed setup does not.
  - http (sqlite, real loop, router and store): the owner gets 200 and another member 403 during the first turn; a stopped first turn keeps the user turn once. Every new test fails with its fix reverted.
- **Gates:**
  - `go build` passes in the default, sqlite and sqliteonly builds.
  - `go vet` passes on agent, pipeline and http (sqlite).
  - agent and pipeline tests pass.
  - http has only failures that also fail on dev on Windows: symlink, SecureCLI, SSH CRLF, and WorkspaceSetup onboarding and leak sweep. SweepsStaleUploads is flaky on dev too.

## Concerns (non-blocking)
- **#1033:** visibility is per process. `UpdateMetadata` only updates the session cache, so other replicas and DB lists (`ListPaged`, the #1022 session list) see the channel when the run ends.
- **Existing race:** cached session fields (`UserID`, `Channel`) are read through `Get` without the store lock. `SetAgentInfo` has the same race already.
- **#1037:**
  - A symlinked or differently-cased argv[1] still makes the migrate script skip itself.
  - The Windows path test is skipped on Linux CI.
- **#1021:** after it lands, cancelling the request context no longer stops the run. The http stop test also calls `AbortRunsForSession`, so it passes on both bases.
