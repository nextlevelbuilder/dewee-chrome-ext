## Root cause

`Router.sessionRuns` (`internal/agent/router.go`) mapped session key to runID with no tenant. Session keys are not unique across tenants. So `RegisterRun` in tenant B overwrote tenant A's entry, and `UnregisterRun` could clear it. Busy, status, inject and abort lookups then read the other tenant's run.

## Fix

- **New key type.** `sessionRunKey{tenantID, sessionKey}`. The tenant comes from `store.TenantIDFromContext` (run ctx at register, caller ctx at lookup).
- **`UnregisterRun`.** Still `CompareAndDelete`, keyed with the tenant stored on the run, so it clears the entry only if it points at the finishing run.
- **New `ctx` parameter** on:
  - `IsSessionBusy`, `SessionRunID`, `InjectMessage`
  - `AbortRunsForSession`, which now filters on `run.TenantID`
  - `AbortRun`. When `sessionKey != ""`, a run in another tenant returns `NotFound`, not `Unauthorized`, so the `Unauthorized` retry fallback in `chat.abort` cannot reach it. An empty `sessionKey` stays an unscoped abort by run ID.
- **Nil tenant.** It is its own bucket. Single-tenant callers that register and look up without a tenant work unchanged.
